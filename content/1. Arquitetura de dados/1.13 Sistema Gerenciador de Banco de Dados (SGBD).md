
Um **Sistema Gerenciador de Banco de Dados (SGBD)** é um software especialista projetado para criar, manter, manipular e controlar o acesso a bancos de dados. Ele atua como uma **camada de abstração** entre as aplicações/usuários e a estrutura de dados armazenada nos discos rígidos ou memória.

```
[ Usuários / Aplicações ] ──(SQL / Comandos)──> [ SGBD ] ──(I/O Físico)──> [ Disco / Memória ]
                                                    │
                                         [ Dicionário de Dados ]
```

## 1. Principais Funções e Módulos do SGBD
Para provas de concurso, um SGBD completo deve prover as seguintes capacidades:
### A. Gerenciamento do Dicionário de Dados / Catálogo
Guarda os **metadados** (dados sobre os dados): nomes de tabelas, tipos de dados, restrições (`PRIMARY KEY`, `FOREIGN KEY`), usuários e permissões. O catálogo é consultado continuamente para validar consultas e aplicar regras de segurança.
### B. Gerenciador de Armazenamento e Buffer
Organiza a alocação de espaço em disco e a transferência de páginas de dados entre o armazenamento secundário e a memória RAM (_Buffer Pool_) para maximizar o desempenho.
### C. Otimizador de Consultas (_Query Optimizer_)
Recebe a instrução SQL, traduz para expressões de Álgebra Relacional e utiliza as estatísticas dos metadados para escolher o **plano de execução de menor custo** (menor tempo e consumo de I/O).

#### 1. Otimização Heurística (Baseada em Regras)
A otimização heurística utiliza um conjunto de regras lógicas e procedurais pré-definidas para reescrever a consulta antes de sua execução. Ela aplica transformações na **Árvore de Álgebra Relacional** para diminuir o volume de dados intermediários o mais rápido possível. Obtém bons resultados na maioria dos casos, mas não há garantias que trabalhará bem em todos os casos e que o melhor plano de execução sera estabelicido
**O que a Cesgranrio cobra sobre Otimização Heurística:**
- **Empurrar Seleções para Baixo (_Pushing Selections Down_):** A regra de ouro. O motor do SGBD deve aplicar os filtros de linhas (`WHERE` / $\sigma$) **antes** de realizar as junções (`JOIN` / $\bowtie$). Fazer um `JOIN` de tabelas inteiras e filtrar no final consome memória desnecessária; filtrar primeiro reduz a entrada da junção.
- **Empurrar Projeções para Baixo (_Pushing Projections Down_):** Eliminar colunas desnecessárias ($\pi$) o quanto antes para reduzir o consumo de memória I/O e barramento.
- **Ordem das Operações:** A ordem de aplicação das junções e seleções comutativas para simplificar o plano.
#### 2. Otimização Sistemática / Custo (Cost-Based Optimization - CBO)
A otimização sistemática avalia os diferentes caminhos físicos de execução possíveis, calcula uma **estimativa de custo de I/O, memória e CPU** para cada plano e escolhe o de menor valor.
**O que a Cesgranrio cobra sobre Otimização Sistemática:**
- **Papel do Catálogo/Dicionário de Dados:** O SGBD só consegue estimar o custo com precisão porque consulta os **metadados e estatísticas** mantidos no Dicionário de Dados (tamanho de tabelas, número de páginas, histogramas e número de valores distintos).
- **Estatísticas Desatualizadas:** Se os metadados do banco estiverem desatualizados (sem rodar o `ANALYZE` ou equivalente no SGBD), o otimizador cometerá erros e escolherá um plano de execução ineficiente.
- **Seleção do Algoritmo de Junção:** A decisão do otimizador de qual algoritmo físico utilizar com base no tamanho estimado dos dados:
    - _Nested Loops:_ Usado para tabelas menores ou com índice.
    - _Hash Join:_ Usado quando as tabelas são volumosas e não há índices.
    - _Sort-Merge Join:_ Usado quando ambas as tabelas já estão ordenadas pelo atributo de junção.
### D. Controle de Concorrência e Gerenciador de Transações
Garante a execução simultânea de múltiplas transações preservando as **propriedades ACID** (Atomicidade, Consistência, Isolamento e Durabilidade) e utilizando mecanismos de bloqueio (_locks_) ou multi-versão (_MVCC_).
### E. Controle de Acesso e Segurança (DCL)
Aplica políticas de autenticação e autorização por meio dos comandos `GRANT` (conceder permissões) e `REVOKE` (remover permissões), além de gerenciar trilhas de auditoria.
### F. Recuperação de Falhas (_Recovery Manager_)
Utiliza arquivos de log de transações (_Write-Ahead Logging - WAL_) para restaurar o banco a um estado consistente após quedas de energia ou falhas de software.
## 2. Processamento de consultas
1. Consulta em uma linguagem de alto nível, como SQL, em que o humano entende
2. Essa consulta para por um compilador e tradutor, que vai olher o contexto léxico, sintático e semântico da consulta, se tudo estiver bem ele transforma em Expressão algébrica relacional ou alguma outra linguagem que permita avançar para os Proximos passos
3. Depois ele executa o otimizador, que vai utilizar consultar metadados, diante das informações do metadados, vai criar um plano de execução com a melhor estratégia de busca de informações daquele momento 
4. Avaliador: É quem vai buscar de fato os dados a partir do plan o de execução  e entregar

## 3. Classificação dos SGBDs (Paradigmas e Casos de Uso)

| **Tipo de SGBD**        | **Paradigma / Modelo**                | **Características Físicas e Casos de Uso**                                                                       | **Exemplos**                          |
| ----------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| **Relacional (RDBMS)**  | Relacional (Tabelas e Esquema Rígido) | Suporte nativo a SQL e propriedades ACID. Ideal para ambientes OLTP (transacionais com forte consistência).      | PostgreSQL, Oracle, MySQL, SQL Server |
| **NoSQL — Documentos**  | Semiestruturado (JSON/BSON)           | Armazena documentos flexíveis e aninhados sem esquema fixo. Excelente para aplicações web e conteúdos dinâmicos. | MongoDB, CouchDB                      |
| **NoSQL — Chave-Valor** | _Hash Table_                          | Acesso direto via chave com baixíssima latência (em memória). Usado para sessões, caches e _queues_.             | Redis, DynamoDB                       |
| **NoSQL — Colunar**     | Família de Colunas (_Column-Family_)  | Dados armazenados fisicamente por coluna. Alta compressão, focado em leitura massiva e Big Data.                 | Apache Cassandra, HBase               |
| **NoSQL — Grafos**      | Vértices e Arestas                    | Usa _Index-Free Adjacency_ (ponteiros diretos entre nós). Ideal para redes sociais e detecção de fraudes.        | Neo4j, Amazon Neptune                 |
| **In-Memory (IMDB)**    | Armazenamento na RAM                  | Mantém os dados na memória principal com persistência opcional no disco. Focado em _throughput_ em tempo real.   | Redis, SAP HANA                       |
## 4. Pegadinhas Recorrentes da Cesgranrio sobre SGBD
1. **Dicionário de Dados Não Guarda os Dados dos Clientes:** O catálogo armazena apenas os **metadados** (a estrutura/definição). Os registros reais ficam nos arquivos de dados do SGBD.
2. **SGBD vs. Banco de Dados:** O Banco de Dados é a **coleção de dados integrados**; o SGBD é o **software** que gerencia e controla essa coleção.
3. **SGBD Relacional garante ACID no nível físico:** Toda transação em um RDBMS deve respeitar as regras ACID de forma nativa via mecanismos de _Lock_ e _Log_ de transações.
