
A **Independência de Dados** é a capacidade de modificar a definição de um esquema em um determinado nível da arquitetura de banco de dados sem que essa alteração force a modificação do esquema do nível imediatamente superior ou cause o reescrever dos programas de aplicação.

Essa propriedade é viabilizada pela **Arquitetura de Três Esquemas (ANSI/SPARC)**, que divide o SGBD nas camadas: **Externa** (Visões), **Conceitual/Lógica** (Esquemas lógicos) e **Interna** (Armazenamento físico).

### Tipos de Independência de Dados

```
Nível Externo (Visões de Usuário / Aplicações)
       ▲
       │  [ 1. Independência Lógica de Dados ]
       ▼
Nível Conceitual / Lógico (Tabelas, Chaves, Constraints)
       ▲
       │  [ 2. Independência Física de Dados ]
       ▼
Nível Interno / Físico (Blocos de Disco, Índices, Partitioning)

```

#### 1. Independência Física de Dados
* **Definição:** É a capacidade de alterar o **esquema interno/físico** (como os dados são armazenados fisicamente) sem precisar alterar o **esquema conceitual/lógico**.
* **O que pode ser alterado no Nível Físico:**
* Alterar estruturas de organização de arquivos (ex.: mudar de organização sequencial para *hash*).
* Criar ou remover índices de desempenho (B-Tree, Bitmap, Hash).
* Mudar a localização física dos arquivos de dados (troca de disco rígido ou *tablespace*).
* Aplicar técnicas de particionamento físico ou compressão de tabelas.
* **Impacto na Aplicação:** Nenhum. As consultas SQL, visões e o código da aplicação continuam funcionando exatamente da mesma forma, alterando apenas a **velocidade/desempenho** da resposta.

#### 2. Independência Lógica de Dados
* **Definição:** É a capacidade de alterar o **esquema conceitual/lógico** (a estrutura global do banco de dados) sem precisar reescrever as **visões de usuário (nível externo)** ou os **programas de aplicação**.
* **O que pode ser alterado no Nível Lógico:**
* Adicionar uma nova tabela ou relacionamento ao esquema.
* Adicionar ou remover atributos/colunas de uma tabela.
* Reorganizar/decompor uma tabela em duas no processo de normalização.
* **Como a Independência Lógica é mantida:** Através de **Visões (Views)** e do **Catálogo/Dicionário de Dados**. Se uma tabela for reestruturada, cria-se uma *view* que simula a estrutura antiga para que as aplicações legadas continuem rodando sem ajustes.
### Mapeamentos (*Mappings*)
Para que a independência de dados funcione, o **Sistema Gerenciador de Banco de Dados (SGBD)** mantém mapeamentos continuados entre os níveis:
1. **Mapeamento Externo/Conceitual:** Conecta cada visão do usuário às tabelas lógicas reais do banco. É responsável pela *independência lógica*.
2. **Mapeamento Conceitual/Interno:** Conecta o esquema relacional/lógico às estruturas físicas de blocos, ponteiros e arquivos em disco. É responsável pela *independência física*.
### Quadro Comparativo: Independência Física vs. Lógica

| Característica                 | Independência Física                                                 | Independência Lógica                                                               |
| ------------------------------ | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **Nível alterado**             | Nível Interno / Físico.                                              | Nível Conceitual / Lógico.                                                         |
| **Dificuldade de Implementar** | **Mais fácil** de ser provida pelos SGBDs.                           | **Mais difícil**, pois afeta diretamente as estruturas das informações do negócio. |
| **Alterações Típicas**         | Índices, partição de arquivo, compressão, disco.                     | Adição/remoção de colunas, tabelas ou normalização.                                |
| **Objetivo Principal**         | Otimização de **desempenho/performance** sem afetar o modelo lógico. | Absorver **evoluções de regras de negócio** sem quebrar as aplicações ativas.      |

### Pegadinhas da Banca Cesgranrio

1. **Independência Absoluta não existe:** Se uma coluna for removida no nível lógico e uma aplicação utilizar diretamente essa coluna (sem uma *View* intermediária), a independência lógica é quebrada.
2. **O Papel dos Metadados:** O SGBD só consegue garantir a independência de dados porque consulta os **metadados (Dicionário de Dados/Catálogo)** para interpretar e traduzir as requisições enviadas pelo usuário até o nível do disco rígido.
3. **Física vs. Lógica:** Questões costumam inverter as definições, afirmando que a *criação de um índice* é um exemplo de *independência lógica* (na verdade, é **física**).
