
A **Linguagem de Definição de Dados** (DDL - _Data Definition Language_) é o subconjunto da linguagem SQL responsável por criar, alterar, reestruturar e excluir os objetos (esquemas, tabelas, índices, visões, restrições) dentro de um Sistema Gerenciador de Banco de Dados (SGBD).
## 1. Principais Comandos DDL

|**Comando DDL**|**Função Principal**|**Impacto no SGBD**|
|---|---|---|
|**`CREATE`**|Cria novos objetos no banco de dados (tabelas, índices, visões, esquemas, _triggers_).|Insere novas definições de estrutura no catálogo/metadados.|
|**`ALTER`**|Modifica a estrutura de um objeto já existente sem destruí-lo (adiciona/remove colunas, altera tipos de dados e adiciona restrições).|Atualiza a definição do objeto no dicionário de dados.|
|**`DROP`**|Remove permanentemente um objeto e toda a sua estrutura do banco de dados.|Apaga a definição e libera os blocos físicos alocados.|
|**`TRUNCATE`**|Esvazia todos os dados de uma tabela de forma rápida.|**Classificado como DDL** (não DML). Desaloca páginas de memória diretamente no SGBD.|
|**`RENAME`**|Altera o nome de um objeto existente (tabela, coluna, etc.).|Atualiza o identificador textual nos metadados.|
## 2. Detalhamento dos Comandos e Sintaxes Avançadas

### A. `CREATE`
#### Restrições (Constraints):
- `PRIMARY KEY`: Define a chave primária física.
- `FOREIGN KEY`: Garante a integridade referencial.
- `NOT NULL`: Impede valores ausentes.
- `UNIQUE`: Garante que valores de uma coluna não se repitam.
- `CHECK`: Valida condições lógicas para aceitar um dado (ex.: `CHECK (Idade >= 18)`).
#### TABELA (`CREATE TABLE`) e Restrições de Integridade (_Constraints_)
A criação física mapeia o modelo lógico aplicando restrições nativas no nível das tabelas ou colunas:

```sql
CREATE TABLE funcionario (
    matricula BIGINT NOT NULL,
    nome VARCHAR(150) NOT NULL,
    cpf CHAR(11) NOT NULL,
    salario NUMERIC(10, 2) NOT NULL,
    cod_depto INT NOT NULL,
    data_admissao DATE DEFAULT CURRENT_DATE,
    -- Setar valor padão para valores de entrada null
    nacionalidade CHAR(2) SET DEFAULT 'BR',
    
    -- Restrição de Chave Primária (PK)
    CONSTRAINT pk_funcionario PRIMARY KEY (matricula),
    
    -- Restrição de Unicidade (UNIQUE)
    CONSTRAINT unq_funcionario_cpf UNIQUE (cpf),
    
    -- Restrição de Validação de Domínio (CHECK)
    CONSTRAINT chk_funcionario_salario CHECK (salario > 0),
    
    -- Restrição de Integridade Referencial (FK)
    CONSTRAINT fk_funcionario_depto 
        FOREIGN KEY (cod_depto) 
        REFERENCES departamento(cod_depto)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);
```

#### ÍNDICES (`CREATE INDEX`)
Estruturas físicas (como B-Tree e Hash) criadas para otimizar o desempenho de buscas em consultas `SELECT`:
```sql
CREATE INDEX idx_func_nome ON funcionario(nome);
```
#### VISÕES (`CREATE VIEW`)
Tabelas virtuais baseadas no resultado de um `SELECT`, usadas para simplificar consultas complexas e aplicar regras de segurança de acesso:
```sql
CREATE VIEW vw_func_salarios AS
    SELECT matricula, nome, salario FROM funcionario WHERE salario > 5000;
```
#### DOMINIO (`CREATE DOMAIN`)
Criar uma restrição ao tipo de dado que eu posso colocar dentro de um atributo ou relação. Caso tenha uma violação, o SGBD rejeita a query e irá lançar um erro;
```sql
CREATE DOMAIN TIPO_ID AS CHAR(4); -- O atributo que estiver com esse dominio só poderá ter 4 caracters

CREATE DOMAIN D_NUM AS INTEGER CHECK (VALUE > 0 AND VALUE < 21); --  O atributo será do tipo inteiro e ele fará uma checagem se esta no intervalo entre 0 e 21.

-- Uso dos dominios
CREATE TABLE departamento (
	id TIPO_ID NOT NULL,
	numero D_NUM
);
```

#### ASSERÇÃO (`CREATE ASSERTION`)
Uma **asserção** é uma regra de integridade declarativa criada como um objeto independente no banco de dados para garantir validações de negócio complexas que **envolvem duas ou mais tabelas ao mesmo tempo**.
* **Diferença para o `CHECK`:** O comando `CHECK` fica atrelado à definição de **uma única tabela ou coluna**. Se você precisa garantir uma condição que cruza dados de tabelas diferentes, o padrão ANSI SQL exige o uso de uma **Asserção**.
* **Como funciona:** O SGBD avalia a condição do `CHECK` dentro da asserção a cada operação DML (`INSERT`, `UPDATE`, `DELETE`). Se a condição for avaliada como `FALSE`, a transação é cancelada e o banco faz *rollback*.
##### Sintaxe no SQL Padrão (ANSI)

```sql
CREATE ASSERTION nome_da_assercao
CHECK ( condicao_logica );

```
##### Exemplo Prático de Concurso
**Cenário:** O banco possui duas tabelas: `projeto` e `funcionario`. O departamento exige a seguinte regra de negócio: *"O custo total acumulado dos projetos não pode ser maior do que a soma do orçamento da empresa disponível na tabela de configurações"*.
**Código da Asserção:**
```sql
CREATE ASSERTION chk_orcamento_projeto
CHECK (
    (SELECT SUM(custo) FROM projeto) <= (SELECT orcamento_total FROM configuracao)
);

```
#### Gatilhos (`CREATET TRIGGER`)

Um **Trigger** é um procedimento armazenado (*stored procedure*) especial que é **disparado automaticamente** pelo SGBD quando um evento específico de modificação de dados (DML: `INSERT`, `UPDATE` ou `DELETE`) ocorre em uma tabela.

##### Principais Objetivos de Uso
* **Garantir Regras de Negócio Complexas:** Validar dados cruzando múltiplas tabelas (substituindo a `ASSERTION` na prática).
* **Auditoria de Dados:** Registrar o histórico de alterações (quem alterou, quando e qual era o valor antigo).
* **Integridade Referencial Customizada:** Executar atualizações ou exclusões em cascata personalizadas.
* **Campos Calculados e Derivados:** Atualizar o estoque de um produto automaticamente após a inserção de uma venda.

##### Estrutura e Componentes de um Trigger

A definição de um gatilho exige três especificações principais:

1. **Momento do Disparo (*Timing*):**
* **`BEFORE`:** Executado *antes* que a alteração seja gravada no banco (usado para validações e formatação de dados).
* **`AFTER`:** Executado *depois* que a alteração foi aplicada na tabela (usado para auditoria e sincronização com outras tabelas).
* **`INSTEAD OF`:** Executado *em vez do* comando DML original (muito utilizado em **Views** não atualizáveis).

2. **Evento Desencadeador (*Event*):**
* `INSERT`, `UPDATE` ou `DELETE` (ou combinações destes).

3. **Nível de Execução (*Granularity*):**
* **`FOR EACH ROW` (Nível de Linha):** O gatilho roda **uma vez para cada linha** afetada pelo comando SQL.
* **`FOR EACH STATEMENT` (Nível de Instrução):** O gatilho roda **apenas uma vez** para todo o comando SQL, independentemente de quantas linhas foram modificadas.

##### Variáveis Especiais: `OLD` e `NEW`
Triggers de nível de linha (`FOR EACH ROW`) possuem acesso a duas tabelas/variáveis pseudônimas na memória para comparar o estado do dado:

| Operação DML | Variável `OLD`                          | Variável `NEW`                                 |
| ------------ | --------------------------------------- | ---------------------------------------------- |
| **`INSERT`** | *Nulo* (`NULL`)                         | Contém os dados que **estão sendo inseridos**. |
| **`UPDATE`** | Contém os dados **antes da alteração**. | Contém os dados **novos após a alteração**.    |
| **`DELETE`** | Contém os dados que **foram apagados**. | *Nulo* (`NULL`) |

##### Sintaxe Básica em SQL Padrão

```sql
CREATE TRIGGER nome_do_trigger
AFTER UPDATE ON funcionario
FOR EACH ROW
WHEN (NEW.salario <> OLD.salario) -- (Opcional) Condição de disparo
BEGIN
    -- Código de auditoria armazenando o valor antigo na tabela de histórico
    INSERT INTO auditoria_salario(matricula, salario_antigo, data_alteracao)
    VALUES (OLD.matricula, OLD.salario, CURRENT_DATE);
END;

```
### B. `ALTER TABLE` (Modificações Estruturais)
Permite alterar a definição de tabelas em produção:
- **Adicionar Coluna:**
    ```sql
    ALTER TABLE funcionario ADD COLUMN email VARCHAR(100);
    ```
- **Remover Coluna:**
    ```sql
    -- Se propagar para outros objetos que dependem desse atributo
    ALTER TABLE funcionario DROP COLUMN endereco CASCADE;
    
    -- Ele verifica alguem que dependa dessa atributo, se existir, ele não vai permitir a exclusão
	ALTER TABLE funcionario DROP COLUMN endereco RESTRICT;
    ```
- **Modificar Tipo/Propriedades da Coluna:**
    ```sql
    ALTER TABLE funcionario ALTER COLUMN nome TYPE VARCHAR(200);
	ALTER TABLE funcionario ALTER COLUMN atributo_qualquer SET DEFAULT 'valor';
    ```
- **Adicionar Restrição Aposteriori:**
    ```sql
    ALTER TABLE funcionario ADD CONSTRAINT fk_depto 
        FOREIGN KEY (cod_depto) REFERENCES departamento(cod_depto);
    ```

### C. `TRUNCATE TABLE` vs. `DROP TABLE` vs. `DELETE`

A distinção entre estes comandos é uma das pegadinhas mais recorrentes em exames:
- **`DELETE` (DML):** Remove linhas uma a uma, registra logs para cada linha deletada, dispara _triggers_ de exclusão e permite desfazer via `ROLLBACK`.
- **`TRUNCATE` (DDL):** Remove todos os dados desalocando as páginas do disco rígido. É significativamente mais rápido, zera contadores de colunas auto-incrementais (como `SERIAL`/`IDENTITY`), não dispara _triggers_ de `DELETE` e em vários SGBDs impõe `COMMIT` implícito.
- **`DROP` (DDL):** Apaga os dados **E a estrutura** da tabela. A tabela deixa de existir no catálogo do SGBD.
## 3. Tipos de dados
1. Números: Inteiros vs. Decimais Exatos vs. Ponto Flutuante
	- **`INT` / `BIGINT`:** Usados para chaves primárias (`PK`), chaves estrangeiras (`FK`) e identificadores.
	- **`NUMERIC(p, s)` ou `DECIMAL(p, s)`:** **Cai muito em provas.** É o tipo usado obrigatoriamente para **valores financeiros/monetários (ex.: salários, preços)**.
	    - _Entenda a precisão:_ `NUMERIC(10, 2)` significa 10 dígitos no total ($p$), sendo 2 após a vírgula ($s$).
	- **`FLOAT` / `DOUBLE`:** Usados para aproximações científicas. **Pegadinha da banca:** Nunca use `FLOAT` para dinheiro, pois ele possui erros de arredondamento por representação binária em ponto flutuante.

2. Textos: Tamanho Fixo vs. Tamanho Variável
	- **`CHAR(n)` (Tamanho Fixo):** Aloca sempre exatamente $n$ caracteres na memória, preenchendo com espaços em branco se o texto for menor. Usado para dados de tamanho estritamente fixo (ex.: `CPF` com 11 dígitos, siglas de UF com 2 letras).
	- **`VARCHAR(n)` (Tamanho Variável):** Armazena apenas o tamanho real da string digitada + um pequeno cabeçalho de controle. Usado para nomes, e-mails e descrições flexíveis.
	
3. Data e Hora
	- **`DATE`:** Armazena apenas ano, mês e dia (`AAAA-MM-DD`).
	- **`TIME`:** Armazena apenas o horário (`HH:MM:SS`).
	- **`TIMESTAMP` / `DATETIME`:** Armazena tanto a data quanto a hora.
	- **`DEFAULT CURRENT_DATE` / `NOW()`:** Muito cobrado para preenchimento automático em DDL (ex.: data de cadastro ou admissão).
4. Como a Banca Cobra na Prática (Exemplo de Pegadinha)
A Cesgranrio apresenta um script DDL e pergunta qual das opções atende melhor ao Modelo Lógico proposto ou qual possui um erro de modelagem:
```sql
-- Exemplo de erro que a Cesgranrio explora:
CREATE TABLE funcionario (
    cpf VARCHAR(11),          -- Ineficiente: CPF tem tamanho fixo (deveria ser CHAR(11))
    salario FLOAT,            -- ERRO: Dinheiro não pode ser FLOAT (deveria ser NUMERIC/DECIMAL)
    data_cadastro VARCHAR(10) -- ERRO: Data em texto impede funções nativas de data
);
```

**5. Resumo da Estratégia de Estudo**

|**Tipo de Dado**|**Quando Escolher?**|**Exemplo Prático**|
|---|---|---|
|**`CHAR(n)`**|Dados de tamanho **fixo e previsível**.|`CHAR(11)` para CPF, `CHAR(2)` para UF.|
|**`VARCHAR(n)`**|Textos de **tamanho variável**.|`VARCHAR(150)` para Nome do Funcionário.|
|**`NUMERIC(p, s)`**|**Valores monetários** e precisão exata.|`NUMERIC(10, 2)` para Salários e Preços.|
|**`BIGINT` / `INT`**|Chaves e contadores inteiros.|`BIGINT` para Matrícula ou ID de tabela.|
|**`DATE` / `TIMESTAMP`**|Datas e marcadores temporais.|`DATE` para Data de Nascimento.|

## 5. Pegadinhas e Pontos Críticos da Cesgranrio
1. **`TRUNCATE` é DDL, não DML:** A banca frequentemente coloca o `TRUNCATE` em opções ao lado de `INSERT`, `UPDATE` e `DELETE` para testar se o candidato confunde a remoção de dados com manipulação DML.
2. **`COMMIT` Implícito:** A execução de comandos DDL na maioria dos SGBDs efetiva (efetua o _commit_) automaticamente quaisquer alterações pendentes na transação corrente, tornando o desfazer (`ROLLBACK`) impossível.
3. **Adição de Restrições em Tabelas Populadas:** Executar um `ALTER TABLE` para adicionar uma restrição `NOT NULL` ou `FOREIGN KEY` em uma tabela que já contém dados inconsistentes causará **falha imediata** na execução do comando DDL.
4. **Locks de Tabela (_Table Locking_):** Operações DDL aplicadas sobre tabelas volumosas exigem bloqueio exclusivo no SGBD, impedindo leituras e escritas temporariamente no banco de produção.
