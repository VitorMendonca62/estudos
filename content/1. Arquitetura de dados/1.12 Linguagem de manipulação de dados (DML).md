
A **Linguagem de Manipulação de Dados (DML)** é o subconjunto da SQL utilizado para inserir, recuperar, modificar e excluir dados armazenados nas tabelas de um SGBD.

Ao contrário da DDL (que altera a estrutura/esquema e metadados), a DML atua diretamente sobre as **linhas (tuplas)** das tabelas. Em concursos públicos, o comando `SELECT` é frequentemente tratado no bloco de DML ou isolado na sigla **DQL** (*Data Query Language*).

---

## 1. Comandos Fundamentais da DML

### A. `INSERT` (Inserção de Dados)

Adiciona novos registros a uma tabela. A ordem dos valores passados na cláusula `VALUES` deve corresponder exatamente à ordem dos atributos declarados.

```sql
-- Formato 1: Declarando as colunas explicitamente (Boa Prática)
INSERT INTO funcionario (matricula, nome, salario, cod_depto)
VALUES (1001, 'Maria Silva', 7500.00, 10);

-- Formato 2: Omite as colunas (Exige todos os valores na ordem exata da tabela)
INSERT INTO funcionario
VALUES (1001, 'Maria Silva', 7500.00, 10);

-- Inserção Multi-Linhas (Padrão ANSI SQL)
INSERT INTO departamento (cod_depto, nome_depto)
VALUES 
    (20, 'TI'),
    (30, 'RH'),
    (40, 'Financeiro');

-- Inserção via Subconsulta (INSERT INTO ... SELECT)
-- Copia dados diretamente de outra tabela sem usar a cláusula VALUES
INSERT INTO func_backup (matricula, nome, salario)
SELECT matricula, nome, salario 
FROM funcionario 
WHERE salario > 5000;
```

---

### B. `UPDATE` (Atualização de Registros)

Modifica os valores de uma ou mais colunas em registros já existentes.

```sql
-- Atualização Padrão
UPDATE funcionario
SET salario = salario * 1.10,
    cod_depto = 20
WHERE cod_depto = 10;

-- UPDATE com Subconsulta
UPDATE funcionario
SET salario = salario * 1.05
WHERE cod_depto IN (SELECT cod_depto FROM departamento WHERE nome_depto = 'TI')
```

> **Atenção de Prova:** Executar um `UPDATE` sem a cláusula `WHERE` atualizará **todas as linhas** da tabela indistintamente.

---

### C. `DELETE` (Remoção de Registros)

Exclui uma ou mais linhas de uma tabela com base em uma condição pré-determinada.

```sql
-- Exclusão Padrão
DELETE FROM funcionario
WHERE matricula = 1001;

-- DELETE com Subconsulta
DELETE FROM funcionario
WHERE cod_depto IN (SELECT cod_depto FROM departamento WHERE nome_depto = 'TI')
```

> **Atenção de Prova:** Executar um `DELETE` sem a cláusula `WHERE` apagará **todas as linhas** da tabela.

#### Comparativo Crítico: `DELETE` vs `TRUNCATE`

| Característica | `DELETE` | `TRUNCATE` |
| --- | --- | --- |
| **Categoria SQL** | **DML** | **DDL** |
| **Filtro (`WHERE`)** | Aceita condições (exclusão seletiva). | Não aceita (remove tudo). |
| **Desempenho** | Mais lento (grava registro por registro no *log*). | Muito mais rápido (desaloca páginas de memória). |
| **Triggers** | Dispara *triggers* `BEFORE/AFTER DELETE`. | **Não** dispara *triggers* de exclusão. |
| **Transação** | Permite reverter com `ROLLBACK`. | Impõe `COMMIT` implícito na maioria dos SGBDs. |
| **Auto-Incremento** | Preserva a sequência atual. | Reseta o contador (`AUTO_INCREMENT` / `IDENTITY`). |

---

### D. `MERGE` / *Upsert* (Inserção ou Atualização Condicional)

Combina as operações de `INSERT`, `UPDATE` e `DELETE` em uma única instrução, tomando como base o cruzamento (*join*) entre uma tabela de origem (*source*) e uma de destino (*target*).

```sql
MERGE INTO func_destino AS target
USING func_origem AS source
ON (target.matricula = source.matricula)
WHEN MATCHED THEN
    UPDATE SET target.salario = source.salario, target.nome = source.nome
WHEN NOT MATCHED THEN
    INSERT (matricula, nome, salario) 
    VALUES (source.matricula, source.nome, source.salario);
```

## 2. Consulta de Dados (`SELECT`) e Regras de Processamento

A instrução `SELECT` é responsável por recuperar e filtrar dados.

**Sintaxe Básica:**

```sql
SELECT DISTINCT atributo_1, atributo_2 -- Atributos recuperados
FROM tabela_1, tabela_2                -- Origens dos dados
WHERE condicao_1 AND/OR condicao_2;    -- Filtro de linhas
```

**Seleção Total de Atributos:**

```sql
SELECT * FROM tabela_1;
```

> **Observação sobre Ambiguidade e Produto Cartesiano:**
> Quando a cláusula `FROM` possui mais de uma tabela sem uma condição de junção explícita, o SGBD gera um **Produto Cartesiano**. Caso haja colunas com o mesmo nome em tabelas distintas, você deve obrigatoriamente qualificar o nome do atributo (usando o nome da tabela ou um *alias*) para evitar o **erro de ambiguidade**:

```sql
-- Erro de ambiguidade (se atributo_1 existir em ambas as tabelas)
SELECT atributo_1
FROM tabela_1, tabela_2;

-- Sucesso (Usando Alias)
SELECT t1.atributo_1
FROM tabela_1 AS t1, tabela_2 AS t2;

-- Sucesso (Usando Nome Completo da Tabela)
SELECT tabela_1.atributo_1
FROM tabela_1, tabela_2;
```

---

### 2.1 Ordem Sintática vs. Ordem de Processamento Lógico

As bancas de concurso exploram o fato de que a ordem de execução interna feita pelo motor do SGBD difere da ordem em que o comando é escrito:

$$\text{Ordem Sintática (Escrita):} \quad \mathbf{SELECT} \rightarrow \mathbf{FROM} \rightarrow \mathbf{JOIN} \rightarrow \mathbf{WHERE} \rightarrow \mathbf{GROUP\ BY} \rightarrow \mathbf{HAVING} \rightarrow \mathbf{ORDER\ BY}$$

$$\text{Execução Lógica (SGBD):} \quad \mathbf{FROM/JOIN} \rightarrow \mathbf{WHERE} \rightarrow \mathbf{GROUP\ BY} \rightarrow \mathbf{HAVING} \rightarrow \mathbf{SELECT} \rightarrow \mathbf{DISTINCT} \rightarrow \mathbf{ORDER\ BY} \rightarrow \mathbf{LIMIT/OFFSET}$$

**Consequências Práticas:**

1. **Uso de Apelidos (*Aliases*):** Criados na cláusula `SELECT`, eles **não podem** ser reutilizados dentro do `WHERE` ou do `HAVING`, pois essas cláusulas são processadas *antes* do `SELECT`. Contudo, podem ser usados normalmente no `ORDER BY`.
2. **Posição do `DISTINCT`:** Executado após o `SELECT` e antes do `ORDER BY`, garantindo que a ordenação ocorra apenas sobre o conjunto desduplicado.

---

### 2.2 Uso do `DISTINCT`

Elimina linhas duplicadas no resultado final da consulta.

```sql
SELECT DISTINCT coluna_1, coluna_2
FROM tabela_1;
```

* **Escopo Global:** Aplica-se ao conjunto **completo** de colunas declaradas no `SELECT` (a duplicidade é avaliada pela linha inteira projetada).
* **Posicionamento:** Deve vir imediatamente após a palavra-chave `SELECT`. Escrever `SELECT col1, DISTINCT col2` gera erro de sintaxe.
* **Tratamento de Nulos:** Múltiplos valores `NULL` são considerados duplicados entre si, retornando uma única linha contendo `NULL`.

---

### 2.3 Operador `LIKE` e Caracteres Coringa (*Pattern Matching*)

Realiza a busca por padrões de texto (*string matching*) na cláusula `WHERE`.

| Coringa | Significado | Exemplo | Resultado |
| --- | --- | --- | --- |
| **`%`** | Substitui **zero ou mais** caracteres. | `WHERE nome LIKE 'A%'` | Nomes começando com "A" (Ex: "A", "Ana", "Amanda"). |
| **`_`** | Substitui **exatamente um** caractere. | `WHERE nome LIKE 'A_a'` | Nomes com 3 letras, começando com "A" e terminando com "a" (Ex: "Ana"). |

**Exemplos Práticos:**

* `WHERE email LIKE '%@gmail.com'` $\rightarrow$ Termina com `@gmail.com`.
* `WHERE codigo LIKE 'A__1'` $\rightarrow$ Começa com "A", possui 2 caracteres quaisquer no meio e termina com "1".
* `WHERE nome NOT LIKE 'B%'` $\rightarrow$ Nomes que não começam com a letra "B".

> **Pegadinha de Concurso:** Símbolos como `*` e `?` **não funcionam** como coringas do operador `LIKE` no SQL Padrão (ANSI).

---

### 2.4 Ordenação de Resultados (`ORDER BY`)

Classifica as linhas retornadas em ordem crescente (`ASC`) ou decrescente (`DESC`).

```sql
SELECT atributo_1, atributo_2
FROM tabela_1
ORDER BY atributo_1 ASC, atributo_2 DESC;
```

* **`ASC` (Ascending):** Padrão do sistema caso nada seja especificado (A-Z, 0-9, datas antigas $\rightarrow$ recentes).
* **`DESC` (Descending):** Ordenação decrescente (Z-A, 9-0, datas recentes $\rightarrow$ antigas).
* **Posição Relativa:** Permite ordenar por posições numéricas das colunas indicadas no `SELECT` (ex: `ORDER BY 1, 2`).
* **Restrição do `DISTINCT`/`UNION`:** Se a consulta usar `DISTINCT` ou `UNION`, o `ORDER BY` só poderá utilizar colunas que estejam presentes na lista do `SELECT`.

#### Tratamento de Valores Nulos (`NULL`) na Ordenação

O padrão ANSI SQL prevê o uso explícito de `NULLS FIRST` e `NULLS LAST`:

```sql
SELECT nome, salario FROM funcionario ORDER BY salario DESC NULLS FIRST;
SELECT nome, salario FROM funcionario ORDER BY salario ASC NULLS LAST;
```

**Comportamento Padrão dos SGBDs (Sem declaração explícita):**

* **PostgreSQL / Oracle:** Consideram `NULL` como o maior valor possível. Em `ASC` ficam no final; em `DESC` ficam no início.
* **MySQL / SQL Server:** Consideram `NULL` como o menor valor possível. Em `ASC` ficam no início; em `DESC` ficam no final.

## 3. Junções (*Joins*) e Tratamento de Nulos (`NULL`)

### 3.1 Tipos de Junção

* **`INNER JOIN`:** Retorna apenas a interseção exata entre as tabelas (linhas que possuem correspondência em ambas).
* **`LEFT OUTER JOIN`:** Retorna todas as linhas da tabela à esquerda, completando com `NULL` as colunas da direita sem correspondência.
* **`RIGHT OUTER JOIN`:** Retorna todas as linhas da tabela à direita, completando com `NULL` as colunas da esquerda sem correspondência.
* **`FULL OUTER JOIN`:** Retorna todas as linhas de ambas as tabelas, unindo correspondências e inserindo `NULL` onde não houver par.
* **`CROSS JOIN`:** Produto cartesiano ($N \times M$ linhas). Não é permitido `ON`
```sql
SELECT *
FROM tabela_1
[INNER/LEFT/RIGHT/FULL] JOIN tabela_2 ON tabela_1.atributo = tabela_2.atributo

SELECT *
FROM tabela_1
CROSS JOIN tabela_
```

---

### 3.2 Lógica Trivalente e Valores `NULL`

O valor `NULL` representa a ausência de informação ou dado desconhecido.

* **Operações de Comparação:** A avaliação de comparações diretas com `NULL` utiliza Lógica Trivalente (`TRUE`, `FALSE`, `UNKNOWN`). Expressões como `campo = NULL` ou `campo <> NULL` avaliam para `UNKNOWN` (falso no contexto do `WHERE`). A verificação exige **`IS NULL`** ou **`IS NOT NULL`**.
* **Comportamento em Agregações:** As funções `SUM()`, `AVG()`, `MIN()`, `MAX()` e `COUNT(coluna)` **agregam ignorando os valores `NULL**`.
* **Exceção:** A função **`COUNT(*)`** contabiliza o número total de linhas do conjunto, incluindo valores inteiramente nulos.

## 4. Agrupamento e Filtragem de Agregados

```sql
SELECT depto_id, AVG(salario) AS media_salario
FROM funcionario
WHERE ativo = 'S'                  -- 1. Filtra linhas individuais (antes do agrupamento)
GROUP BY depto_id                  -- 2. Agrupa as linhas restantes
HAVING AVG(salario) > 5000;        -- 3. Filtra os grupos consolidados
```

| Cláusula | Momento de Avaliação | O que filtra? | Aceita Funções de Agregação? |
| --- | --- | --- | --- |
| **`WHERE`** | Antes do `GROUP BY` | Linhas individuais (*tuples*). | **Não** (Gera erro de sintaxe) |
| **`HAVING`** | Depois do `GROUP BY` | Grupos consolidados. | **Sim** |

## 5. CTEs (*Common Table Expressions*) e Funções de Janela

### A. CTEs (`WITH`)

Criam conjuntos de resultados temporários reutilizáveis no escopo de uma única consulta, melhorando a legibilidade e modulação do código.

```sql
WITH VendasRegiao AS (
    SELECT regiao_id, SUM(valor) AS total_vendas
    FROM vendas
    GROUP BY regiao_id
)
SELECT * FROM VendasRegiao WHERE total_vendas > 50000;
```

* **CTEs Recursivas (`WITH RECURSIVE`):** Utilizadas para percorrer dados hierárquicos e estruturas em árvore (ex: organogramas, categorias de produtos).

---

### B. Funções de Janela (*Window Functions* - Cláusula `OVER`)

Realizam cálculos agregados sobre um conjunto de linhas sem colapsar ou agrupar as linhas do resultado original.

**Sintaxe Padrão:**


$$\text{FUNCAO()} \quad \mathbf{OVER} \quad (\mathbf{PARTITION\ BY} \text{ coluna\_agrupamento } \mathbf{ORDER\ BY} \text{ coluna\_ordenacao})$$

* **`ROW_NUMBER()`:** Atribui uma numeração sequencial única para cada linha dentro da partição ($1, 2, 3, 4\dots$).
* **`RANK()`:** Classifica os elementos atribuindo posições idênticas a empates, **pulando** a numeração seguinte (Ex: $1, 2, 2, 4\dots$).
* **`DENSE_RANK()`:** Classifica os elementos atribuindo posições idênticas a empates, **sem pular** a numeração seguinte (Ex: $1, 2, 2, 3\dots$).
* **`LAG(coluna, offset)` / `LEAD(coluna, offset)`:** Acessa o valor de uma linha anterior (`LAG`) ou posterior (`LEAD`) dentro da mesma janela.

## 6. Subconsultas e Operadores de Conjunto

### 6.1 Operadores de Subconsulta

* **`EXISTS`:** Avalia apenas a existência de linhas no resultado da subconsulta. Possui mecanismo de **curto-circuito** (*short-circuit*): interrompe a execução assim que encontra a primeira ocorrência compatível. Convenção de uso em prova: `WHERE EXISTS (SELECT 1 FROM ...)` ou `SELECT *`.
* **`IN`:** Compara um elemento escalar contra uma lista de valores.
* **Pegadinha do `NOT IN` com `NULL`:** Se a subconsulta de um `NOT IN` retornar ao menos um valor `NULL`, a expressão será avaliada como `UNKNOWN` para todas as comparações, fazendo com que a consulta retorne **zero linhas** (resultado vazio).


* **`ANY` / `SOME`:** Sinônimos exatos no SQL Padrão. Exigem operador de comparação prévio (`=`, `>`, `<`, etc.). O trecho `= ANY (...)` equivale ao `IN (...)`.
* **`ALL`:** Exige que a condição seja verdadeira para **todos** os elementos da lista retornada. O trecho `<> ALL (...)` equivale ao `NOT IN (...)`.

---

### 6.2 Operadores de Conjunto (*Set Operators*)

Servem para unir o resultado de duas ou mais instruções `SELECT` independentes.

> **Regra Obrigatória:** As consultas conectadas devem retornar exatamente o **mesmo número de colunas** com **tipos de dados compatíveis**.

```sql
SELECT col1, col2 FROM tabela_A
[ OPERADOR DE CONJUNTO ]
SELECT col1, col2 FROM tabela_B;
```

* **`UNION`:** Unifica os resultados e **remove linhas duplicadas** (executa uma operação interna pesada de ordenação/desduplicação).
* **`UNION ALL`:** Unifica os resultados **preservando todas as duplicatas**. É mais rápido por não exigir ordenação em memória.
* **`INTERSECT`:** Retorna apenas as linhas presentes em **ambos** os conjuntos de dados.
* **`EXCEPT` / `MINUS`:** Retorna as linhas do primeiro conjunto que não existem no segundo conjunto.
* **`EXCEPT`:** Termo adotado no padrão ANSI SQL (PostgreSQL, SQL Server, SQLite).
* **`MINUS`:** Termo adotado no Oracle Database.

## 7. Resumo de Pegadinhas Frequentes da Cesgranrio

1. **Erro no `WHERE` com Agregações:** Nunca utilize funções como `SUM()`, `AVG()` ou `COUNT()` na cláusula `WHERE`. Use a cláusula `HAVING`.
2. **`NOT IN` com `NULL`:** Se o subconjunto retornado contiver `NULL`, a consulta com `NOT IN` resultará em um conjunto vazio.
3. **Erros de Integridade Referencial no DML:** Executar um `DELETE` na tabela pai sem a configuração de `ON DELETE CASCADE` ou `ON DELETE SET NULL` na chave estrangeira (*Foreign Key*) fará o SGBD rejeitar a operação por erro de integridade referencial.
4. **Aliasing no `WHERE`:** Lembre-se da ordem lógica de execução. Você não pode filtrar no `WHERE` usando o nome de uma coluna apelidada no `SELECT`.
