> A matriz registra consultas SQL aplicadas nas provas analisadas. A cobrança tende a apresentar tabelas, algumas linhas e uma consulta para perguntar o resultado ou escolher a instrução correta. `JOIN`, agregação, `NULL`, subconsultas e ordem lógica de processamento possuem alto retorno.

## O que você DEVE MANTER e REVISAR — o “coração” da CESGRANRIO

A CESGRANRIO concentra suas questões de SQL em cinco pilares:

1. **SQL é declarativa (Seções 1 e 2):** a consulta informa **qual resultado** deseja, não o algoritmo físico usado para obtê-lo. **Pegadinha:** ordem escrita, ordem lógica e ordem física de execução são conceitos diferentes.

2. **Álgebra relacional × SQL (Seções 3 a 5):** seleção filtra linhas; projeção escolhe colunas; junção combina relações. SQL permite duplicatas e `NULL`, ao contrário do modelo relacional clássico.

3. **`JOIN` e filtros (Seções 8 e 9):** `INNER JOIN` mantém correspondências; `LEFT JOIN` preserva o lado esquerdo. **Pegadinha:** condição da tabela direita no `WHERE` pode eliminar os nulos e fazer um `LEFT JOIN` comportar-se como interno.

4. **Agregação (Seção 10):** `WHERE` filtra linhas antes dos grupos; `HAVING` filtra grupos depois da agregação. Toda coluna não agregada do `SELECT` deve ser compatível com o `GROUP BY`.

5. **Ordem lógica de processamento (Seção 13):** formação das fontes com `FROM/JOIN/ON → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → paginação`. **Pegadinha:** o alias criado no `SELECT` geralmente não existe quando o `WHERE` é avaliado.

> [!note] Limite deste módulo
> DDL e DML serão aprofundadas em 1.11 e 1.12. Aqui suas subdivisões serão classificadas, mas o estudo prático ficará concentrado em consultas `SELECT`. Planos de execução, índices e otimização pertencem ao tópico 1.17.

## 1. O que é SQL

**SQL — Structured Query Language** é a linguagem padronizada usada para definir, consultar, manipular e controlar dados em sistemas relacionais.

Ela permite, entre outras operações:

- criar e alterar estruturas;
- inserir, atualizar e excluir dados;
- consultar e combinar relações;
- definir restrições;
- controlar privilégios;
- controlar transações.

Exemplo declarativo:

```sql
SELECT nome
FROM empregado
WHERE cod_departamento = 10;
```

A consulta descreve o resultado desejado: nomes dos empregados do departamento 10. Ela não determina se o SGBD usará índice, varredura completa, _hash_ ou outro algoritmo.

> [!warning] Pegadinha CESGRANRIO
> SQL não é somente linguagem de consulta. Ela também contém recursos para definição, manipulação, controle de acesso e transações.

## 2. Características da SQL

### 2.1 Declarativa ou não procedural

O usuário declara **o que** deseja. O SGBD escolhe um plano para obter o resultado.

Isso não significa que a forma da consulta seja irrelevante; consultas equivalentes podem levar o otimizador a alternativas diferentes. O ponto conceitual é que o algoritmo físico não é especificado passo a passo pelo `SELECT`.

### 2.2 Baseada no modelo relacional

SQL foi inspirada no modelo relacional e em operações como seleção, projeção, produto e junção. Porém, não implementa de forma idêntica a álgebra relacional matemática.

### 2.3 Orientada a conjuntos

Uma instrução pode operar sobre várias linhas de uma vez:

```sql
UPDATE empregado
SET reajuste = 0.05
WHERE cod_departamento = 10;
```

Não é necessário percorrer cada empregado explicitamente.

### 2.4 Padronizada, mas com dialetos

SQL possui padronização internacional, mas SGBDs acrescentam diferenças:

- tipos próprios;
- funções específicas;
- formas de paginação;
- extensões procedurais;
- detalhes de DDL e transações.

O núcleo de `SELECT`, `JOIN`, `WHERE`, `GROUP BY` e operações de conjunto é amplamente compartilhado.

### 2.5 Semântica de multiconjunto

Na teoria relacional, uma relação não possui tuplas duplicadas. Em SQL, `SELECT` preserva duplicatas por padrão.

```sql
SELECT cod_departamento
FROM empregado;
```

Pode produzir:

```text
10
10
20
```

Para eliminar repetições:

```sql
SELECT DISTINCT cod_departamento
FROM empregado;
```

### 2.6 Suporte a `NULL` e lógica de três valores

SQL admite `NULL` e trabalha, nas comparações, com:

```text
TRUE
FALSE
UNKNOWN
```

O `WHERE` mantém somente linhas cujo predicado seja `TRUE`.

### 2.7 Resultado sem ordem implícita

Sem `ORDER BY`, a ordem das linhas não é garantida.

```sql
SELECT nome
FROM empregado
ORDER BY nome;
```

> [!warning] Pegadinhas CESGRANRIO
>
> - padronização não elimina diferenças entre dialetos;
> - “orientada a conjuntos” não impede o resultado de conter duplicatas;
> - PK ou índice não substituem `ORDER BY`;
> - SQL declarativa não significa ordem lógica inexistente.

## 3. Álgebra relacional

A **álgebra relacional** é uma linguagem formal e procedural composta por operadores que recebem uma ou mais relações e produzem outra relação.

```text
relação de entrada
→ operador relacional
→ relação de saída
```

Essa propriedade é chamada de **fechamento**: como o resultado também é relação, operadores podem ser combinados.

Exemplo:

```text
π nome (σ cod_departamento = 10 (EMPREGADO))
```

Leitura:

1. selecionar empregados do departamento 10;
2. projetar somente o atributo `nome`.

Aproximação em SQL:

```sql
SELECT nome
FROM empregado
WHERE cod_departamento = 10;
```

> [!warning] Pegadinha CESGRANRIO
> SQL é declarativa; a álgebra relacional é normalmente classificada como procedural, pois a expressão indica uma composição de operações para produzir o resultado.

## 4. Operadores fundamentais da álgebra relacional

### 4.1 Seleção — `σ`

Escolhe tuplas que satisfazem um predicado.

```text
σ salario > 10000 (EMPREGADO)
```

```sql
SELECT *
FROM empregado
WHERE salario > 10000;
```

- atua horizontalmente;
- não altera o grau da relação;
- pode reduzir a cardinalidade.

### 4.2 Projeção — `π`

Escolhe atributos.

```text
π nome, salario (EMPREGADO)
```

```sql
SELECT nome, salario
FROM empregado;
```

- atua verticalmente;
- altera o grau;
- na álgebra relacional, elimina duplicatas;
- em SQL, exige `DISTINCT` para reproduzir essa eliminação.

### 4.3 Renomeação — `ρ`

Renomeia relação ou atributos, sendo útil em autorrelacionamentos.

```sql
SELECT e.nome AS empregado,
       g.nome AS gestor
FROM empregado AS e
```

`e` e `g` são aliases para dois papéis da mesma tabela.

### 4.4 Produto cartesiano — `×`

Combina cada tupla da primeira relação com cada tupla da segunda.

```sql
SELECT *
FROM empregado
CROSS JOIN projeto;

SELECT *
FROM empregado, projeto
```

Se `EMPREGADO` possui `m` linhas e `PROJETO` possui `n`, o resultado possui `m × n` linhas.

### 4.5 União — `∪`

Reúne tuplas de relações compatíveis, eliminando duplicatas.

```sql
SELECT cpf FROM empregado_ativo
UNION
SELECT cpf FROM empregado_afastado;
```

### 4.6 Diferença — `−`

Retorna tuplas da primeira relação ausentes na segunda.

```sql
SELECT matricula FROM empregado
EXCEPT
SELECT matricula FROM alocacao;
```

O nome do operador SQL pode variar entre produtos; alguns utilizam `MINUS`.

> [!warning] Pegadinhas CESGRANRIO
>
> - seleção filtra **linhas**; projeção escolhe **colunas**;
> - projeção relacional elimina duplicatas; `SELECT` SQL comum não;
> - produto cartesiano possui cardinalidade multiplicativa;
> - `UNION` elimina duplicatas; `UNION ALL` preserva.

## 5. Operadores derivados e junções

### 5.1 Interseção — `∩`

Retorna tuplas presentes nos dois operandos.

```sql
SELECT matricula FROM empregado_certificado
INTERSECT
SELECT matricula FROM empregado_projeto_critico;
```

### 5.2 Junção theta

Combina tuplas segundo uma condição geral:

```text
EMPREGADO ⋈ EMPREGADO.cod_departamento = DEPARTAMENTO.cod_departamento DEPARTAMENTO
```

```sql
SELECT e.nome, d.nome
FROM empregado AS e
JOIN departamento AS d
  ON d.cod_departamento = e.cod_departamento;
```

### 5.3 Equijunção

É uma junção theta cuja condição usa igualdade. Pode manter as duas colunas de junção no resultado.

### 5.4 Junção natural

Combina automaticamente atributos de mesmo nome e remove uma das colunas repetidas de junção.

```sql
SELECT *
FROM empregado
NATURAL JOIN departamento;
```

Apesar de concisa, pode ser arriscada: adicionar nova coluna com mesmo nome muda silenciosamente a condição.
#### 5.5 Junções Externas (Outer Joins)
Preservam as tuplas de uma ou ambas as relações que não possuem correspondência do outro lado, preenchendo as lacunas com valores nulos (`NULL`).
1. **Junção Externa à Esquerda (⧑):** Retorna todas as tuplas da relação da esquerda ($R$), mesmo sem correspondente em $S$.
2. **Junção Externa à Direita (⧒):** Retorna todas as tuplas da relação da direita ($S$), mesmo sem correspondente em $R$.
3. **Junção Externa Completa (⟗):** Retorna todas as tuplas de ambas as relações, preenchendo com `NULL` onde não houver casamento de chaves.
### 5.5 Divisão relacional

Expressa consultas do tipo “para todos”:

```text
Quais empregados participaram de todos os projetos obrigatórios?
```

SQL não possui operador `DIVIDE` comum; a ideia costuma ser expressa com `NOT EXISTS` duplo ou agregação. Para este módulo, basta reconhecer a semântica universal.

### 5.6 Compatibilidade de união

União, interseção e diferença exigem:

- mesma quantidade de colunas;
- tipos/domínios correspondentes compatíveis;
- correspondência pela posição.

Os nomes finais das colunas são normalmente determinados pela primeira consulta.

## 6. Álgebra relacional × SQL

| Álgebra relacional | SQL |
|---|---|
| relação é conjunto | resultado normalmente é multiconjunto |
| não possui duplicatas | duplicatas permanecem sem `DISTINCT` |
| modelo clássico não usa `NULL` | admite `NULL` e `UNKNOWN` |
| projeção elimina duplicatas | lista do `SELECT` não elimina automaticamente |
| seleção `σ` | `WHERE` |
| projeção `π` | colunas do `SELECT` |
| produto `×` | `CROSS JOIN` |
| junção `⋈` | `JOIN ... ON` |
| união `∪` | `UNION` |
| diferença `−` | `EXCEPT`/`MINUS` |
| renomeação `ρ` | `AS` |

SQL também oferece recursos além da álgebra relacional básica, como agregação, ordenação, tratamento de `NULL` e funções analíticas.

## 7. Subdivisões da SQL

As siglas são uma classificação didática comum. O padrão e diferentes autores podem agrupar instruções de outra forma.

### 7.1 DDL — Data Definition Language

Define e altera estruturas.

Comandos típicos:

```text
CREATE
ALTER
DROP
TRUNCATE
```

Também define restrições como PK, FK, `UNIQUE` e `CHECK`.

### 7.2 DML — Data Manipulation Language

Manipula os dados armazenados.

```text
INSERT
UPDATE
DELETE
MERGE
```

### 7.3 DQL — Data Query Language

Classificação didática usada para consulta:

```text
SELECT
```

No padrão SQL e em parte da literatura, `SELECT` pode ser incluído na DML. Em questões, observe a convenção explicitada.

### 7.4 DCL — Data Control Language

Controla privilégios.

```text
GRANT
REVOKE
```

### 7.5 TCL — Transaction Control Language

Controla transações.

```text
COMMIT
ROLLBACK
SAVEPOINT
SET TRANSACTION
```

### 7.6 Quadro comparativo

| Subdivisão | Finalidade | Exemplos |
|---|---|---|
| DDL | definir estruturas | `CREATE`, `ALTER`, `DROP` |
| DML | manipular linhas | `INSERT`, `UPDATE`, `DELETE`, `MERGE` |
| DQL | consultar | `SELECT` |
| DCL | controlar privilégios | `GRANT`, `REVOKE` |
| TCL | controlar transações | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

> [!warning] Pegadinhas CESGRANRIO
>
> - `ALTER` é DDL; `UPDATE` é DML;
> - `DELETE` remove linhas; `DROP` remove o objeto;
> - `GRANT` não confirma transação; é DCL;
> - a classificação de `SELECT` como DQL ou DML depende da convenção da questão.

## 8. Estrutura básica do `SELECT`
A Cesgranrio costuma testar se o candidato entende que a **ordem de execução interna** de uma consulta difere da **ordem sintática escritas**:

$$\text{Sintática:} \quad \mathbf{SELECT} \rightarrow \mathbf{FROM} \rightarrow \mathbf{JOIN} \rightarrow \mathbf{WHERE} \rightarrow \mathbf{GROUP BY} \rightarrow \mathbf{HAVING} \rightarrow \mathbf{ORDER BY}$$

$$\text{Execução Lógica:} \quad \mathbf{FROM/JOIN} \rightarrow \mathbf{WHERE} \rightarrow \mathbf{GROUP BY} \rightarrow \mathbf{HAVING} \rightarrow \mathbf{SELECT} \rightarrow \mathbf{DISTINCT} \rightarrow \mathbf{ORDER BY} \rightarrow \mathbf{LIMIT/OFFSET}$$

> **Ponto Crítico:** Não é possível usar apelidos (_aliases_) criados na cláusula `SELECT` dentro da cláusula `WHERE` ou `HAVING`, pois o `WHERE`/`HAVING` é avaliado **antes** do `SELECT`. No entanto, eles podem ser usados no `ORDER BY`.


```sql
SELECT [DISTINCT] expressão
FROM fonte
[JOIN outra_fonte ON condição]
[WHERE condição_de_linha]
[GROUP BY expressão_de_grupo]
[HAVING condição_de_grupo]
[ORDER BY expressão [ASC | DESC]];
```

Exemplo:

```sql
SELECT d.nome,
       COUNT(*) AS quantidade_empregados,
       AVG(e.salario) AS media_salarial
FROM departamento AS d
JOIN empregado AS e
  ON e.cod_departamento = d.cod_departamento
WHERE e.ativo = 'S'
GROUP BY d.nome
HAVING COUNT(*) >= 5
ORDER BY media_salarial DESC;
```

Leitura em linguagem natural:

1. combinar departamentos e empregados;
2. manter apenas empregados ativos;
3. formar grupos por departamento;
4. manter grupos com pelo menos cinco empregados;
5. calcular quantidade e média;
6. ordenar pela média decrescente.

## 9. `JOIN`: tipos essenciais

Considere:

```text
DEPARTAMENTO
10 | Operações
20 | TI
30 | Jurídico

EMPREGADO
1 | Ana   | 10
2 | Beto  | 10
3 | Caio  | NULL
```

### 9.1 `INNER JOIN`

Mantém apenas correspondências.

```sql
SELECT e.nome, d.nome
FROM empregado AS e
INNER JOIN departamento AS d
  ON d.cod_departamento = e.cod_departamento;
```

Resultado:

```text
Ana  | Operações
Beto | Operações
```

### 9.2 `LEFT OUTER JOIN`

Preserva todas as linhas da esquerda e preenche com `NULL` quando não há correspondência.

```sql
SELECT d.nome, e.nome
FROM departamento AS d
LEFT JOIN empregado AS e
  ON e.cod_departamento = d.cod_departamento;
```

Resultado conceitual:

```text
Operações | Ana
Operações | Beto
TI        | NULL
Jurídico  | NULL
```

### 9.3 `RIGHT JOIN` e `FULL OUTER JOIN`

- `RIGHT JOIN`: preserva o lado direito;
- `FULL OUTER JOIN`: preserva ambos os lados, correspondentes ou não.

O suporte e a sintaxe podem variar em alguns produtos.

### 9.4 `CROSS JOIN`

Produz o produto cartesiano.

### 9.5 `SELF JOIN`

Não é um operador separado: é a mesma tabela usada em papéis diferentes com aliases.

```sql
SELECT e.nome AS empregado,
       g.nome AS gestor
FROM empregado AS e
LEFT JOIN empregado AS g
  ON g.matricula = e.matricula_gestor;
```

## 10. Filtros: `ON`, `WHERE` e `HAVING`

### 10.1 `ON`

Define como as fontes são combinadas. Em junções externas, influencia quais linhas recebem correspondência sem necessariamente eliminar a linha preservada.

### 10.2 `WHERE`

Filtra linhas após a formação das fontes e junções.

```sql
SELECT *
FROM empregado
WHERE salario > 10000;
```

Não use função de agregação diretamente no `WHERE` do mesmo nível:

```sql
-- incorreto no mesmo nível
WHERE COUNT(*) >= 5
```

### 10.3 `HAVING`

Filtra grupos após `GROUP BY` e agregação.

```sql
SELECT cod_departamento, COUNT(*)
FROM empregado
GROUP BY cod_departamento
HAVING COUNT(*) >= 5;
```

### 10.4 Pegadinha do `LEFT JOIN`

Consulta que preserva todos os departamentos, considerando ativos na correspondência:

```sql
SELECT d.nome, e.nome
FROM departamento AS d
LEFT JOIN empregado AS e
  ON e.cod_departamento = d.cod_departamento
 AND e.ativo = 'S';
```

Consulta que elimina departamentos sem empregado ativo:

```sql
SELECT d.nome, e.nome
FROM departamento AS d
LEFT JOIN empregado AS e
  ON e.cod_departamento = d.cod_departamento
WHERE e.ativo = 'S';
```

No segundo caso, as linhas sem correspondência possuem `e.ativo = NULL`; o predicado resulta em `UNKNOWN` e elas são removidas.

## 11. Agregação e agrupamento

Funções frequentes:

| Função | Resultado |
|---|---|
| `COUNT(*)` | quantidade de linhas |
| `COUNT(coluna)` | quantidade de valores não nulos |
| `COUNT(DISTINCT coluna)` | quantidade de valores distintos não nulos |
| `SUM(coluna)` | soma dos valores não nulos |
| `AVG(coluna)` | média dos valores não nulos |
| `MIN(coluna)` | menor valor não nulo |
| `MAX(coluna)` | maior valor não nulo |

### 11.1 `COUNT(*)` × `COUNT(coluna)`

Considere salários:

```text
1000
2000
NULL
```

```text
COUNT(*)       = 3
COUNT(salario) = 2
AVG(salario)   = 1500
```

`AVG` ignora o `NULL`; não o trata como zero.

### 11.2 Colunas agrupadas

```sql
SELECT cod_departamento,
       COUNT(*)
FROM empregado
GROUP BY cod_departamento;
```

Em uma consulta agrupada, colunas não agregadas selecionadas precisam participar do agrupamento segundo as regras aplicáveis.

> [!warning] Pegadinhas CESGRANRIO
>
> - `COUNT(*)` conta linhas; `COUNT(coluna)` ignora nulos;
> - `AVG` ignora nulos;
> - `WHERE` não substitui `HAVING` para condição agregada;
> - agrupamento ocorre antes da projeção final.

## 12. `NULL` e lógica de três valores

### 12.1 Teste correto

```sql
WHERE cod_departamento IS NULL
```

Não:

```sql
WHERE cod_departamento = NULL
```

### 12.2 `COALESCE`

Retorna o primeiro argumento não nulo:

```sql
SELECT nome,
       COALESCE(email, 'não informado') AS email_exibido
FROM empregado;
```

### 12.3 `NOT IN` com `NULL`

Uma lista ou subconsulta contendo `NULL` pode fazer `NOT IN` resultar em `UNKNOWN` e produzir resultado inesperado.

```sql
WHERE matricula NOT IN (1, 2, NULL)
```

Para antijunções, `NOT EXISTS` costuma expressar a intenção com maior segurança:

```sql
SELECT e.*
FROM empregado AS e
WHERE NOT EXISTS (
    SELECT 1
    FROM alocacao AS a
    WHERE a.matricula = e.matricula
);
```

> [!warning] Pegadinha CESGRANRIO
> `NULL` não é valor igual a outro `NULL`. Comparações comuns com ele produzem `UNKNOWN`; use `IS NULL` ou `IS NOT NULL`.

## 13. Ordem lógica de processamento

A ordem em que as cláusulas são escritas não é a ordem lógica em que produzem o resultado.

### 13.1 Ordem escrita

```text
SELECT
FROM
JOIN / ON
WHERE
GROUP BY
HAVING
ORDER BY
```

### 13.2 Ordem lógica simplificada

```mermaid
flowchart LR
    A["1. FROM / JOIN / ON"] --> B["2. WHERE"]
    B --> C["3. GROUP BY"]
    C --> D["4. Agregações"]
    D --> E["5. HAVING"]
    E --> F["6. SELECT"]
    F --> G["7. DISTINCT"]
    G --> H["8. Operações de conjunto"]
    H --> I["9. ORDER BY"]
    I --> J["10. OFFSET/FETCH ou LIMIT"]
```

Uma forma curta para memorizar:

```text
FROM/JOIN/ON → WHERE → GROUP BY → HAVING
→ SELECT → DISTINCT → ORDER BY → LIMIT
```

Detalhes podem variar conforme recursos usados e modelo didático, mas essa sequência resolve a maioria das questões.

### 13.3 Consequências práticas

#### Alias do `SELECT` no `WHERE`

```sql
SELECT salario * 12 AS salario_anual
FROM empregado
WHERE salario_anual > 120000; -- geralmente inválido
```

O `WHERE` é avaliado antes de o alias `salario_anual` ser criado.

Use:

```sql
SELECT salario * 12 AS salario_anual
FROM empregado
WHERE salario * 12 > 120000;
```

O alias costuma poder ser usado em `ORDER BY`, pois a ordenação ocorre depois da projeção:

```sql
SELECT salario * 12 AS salario_anual
FROM empregado
ORDER BY salario_anual DESC;
```

#### `WHERE` antes de `GROUP BY`

Linhas eliminadas pelo `WHERE` não participam dos grupos nem das agregações.

#### `HAVING` depois da agregação

O `HAVING` pode testar `COUNT`, `SUM` e outras funções agregadas.

#### `DISTINCT` depois do `SELECT`

As expressões são projetadas e depois as linhas duplicadas do resultado são eliminadas.

#### `ORDER BY` perto do fim

A ordenação é aplicada ao resultado projetado, razão pela qual pode usar alias da lista do `SELECT` em muitos SGBDs.

> [!warning] Pegadinha CESGRANRIO
> A ordem lógica não é necessariamente o plano físico real. O otimizador pode reorganizar operações desde que preserve a semântica da consulta.

## 14. Subconsultas e `EXISTS` — núcleo necessário

### 14.1 Subconsulta escalar

Retorna um único valor:

```sql
SELECT nome
FROM empregado
WHERE salario > (
    SELECT AVG(salario)
    FROM empregado
);
```

### 14.2 Subconsulta com `IN`

```sql
SELECT nome
FROM empregado
WHERE cod_departamento IN (
    SELECT cod_departamento
    FROM departamento
    WHERE localizacao = 'RJ'
);
```

### 14.3 Subconsulta correlacionada

Referencia a linha da consulta externa:

```sql
SELECT e.nome
FROM empregado AS e
WHERE EXISTS (
    SELECT 1
    FROM alocacao AS a
    WHERE a.matricula = e.matricula
);
```

`EXISTS` é verdadeiro quando a subconsulta produz pelo menos uma linha; os valores selecionados internamente não importam para esse teste.

## 15. Operações de conjunto em SQL

### 15.1 `UNION`

Combina e elimina duplicatas.

### 15.2 `UNION ALL`

Combina e preserva duplicatas.

### 15.3 `INTERSECT`

Mantém linhas presentes em ambos os resultados.

### 15.4 `EXCEPT`

Mantém linhas da primeira consulta ausentes na segunda.

### 15.5 `ORDER BY`

Em uma composição por operação de conjunto, o `ORDER BY` final ordena o resultado combinado:

```sql
SELECT nome FROM empregado_ativo
UNION
SELECT nome FROM empregado_afastado
ORDER BY nome;
```

> [!warning] Pegadinha CESGRANRIO
> `UNION` é diferente de `JOIN`: `UNION` empilha linhas compatíveis; `JOIN` combina colunas segundo uma condição.

## 16. Exemplo integrado

Considere:

```text
DEPARTAMENTO(cod_departamento PK, nome)
EMPREGADO(matricula PK, nome, salario, cod_departamento FK, ativo)
```

Consulta:

```sql
SELECT d.nome,
       COUNT(e.matricula) AS quantidade,
       AVG(e.salario) AS media
FROM departamento AS d
LEFT JOIN empregado AS e
  ON e.cod_departamento = d.cod_departamento
 AND e.ativo = 'S'
GROUP BY d.nome
HAVING COUNT(e.matricula) >= 2
ORDER BY media DESC;
```

### 16.1 Processamento lógico

1. `FROM`: obtém `DEPARTAMENTO`;
2. `LEFT JOIN/ON`: associa empregados ativos e preserva departamentos;
3. não há `WHERE`;
4. `GROUP BY`: forma um grupo por nome de departamento;
5. calcula contagem e média;
6. `HAVING`: mantém grupos com ao menos dois empregados ativos;
7. `SELECT`: projeta nome, quantidade e média;
8. `ORDER BY`: ordena pela média decrescente.

### 16.2 Por que `COUNT(e.matricula)`

Em departamento sem empregado, o `LEFT JOIN` gera linha com colunas de `e` nulas:

```text
COUNT(*)           contaria a linha preservada
COUNT(e.matricula) não conta a matrícula nula
```

Essa distinção é frequente em questões com junção externa.

## 17. Erros frequentes

### 17.1 Confundir seleção com projeção

```text
seleção = linhas
projeção = colunas
```

### 17.2 Confundir `UNION` com `JOIN`

```text
UNION = acrescenta linhas
JOIN  = acrescenta/combina colunas
```

### 17.3 Usar `= NULL`

Use `IS NULL`.

### 17.4 Usar agregação no `WHERE`

Condições de grupo pertencem ao `HAVING`.

### 17.5 Presumir ordem sem `ORDER BY`

Não há garantia.

### 17.6 Transformar `LEFT JOIN` em interno

Filtro da tabela opcional no `WHERE` elimina linhas com `NULL`.

### 17.7 Esquecer duplicatas

`SELECT` e `UNION ALL` podem preservá-las; `DISTINCT` e `UNION` as eliminam.

## 20. Checklist de pegadinhas

- [ ] SQL é declarativa e orientada a conjuntos.
- [ ] SQL pode produzir duplicatas; relação matemática não.
- [ ] Seleção filtra linhas; projeção escolhe colunas.
- [ ] Projeção relacional elimina duplicatas; `SELECT` comum não.
- [ ] `UNION` elimina duplicatas; `UNION ALL` preserva.
- [ ] `JOIN` combina colunas; `UNION` empilha linhas.
- [ ] Sem `ORDER BY`, não há ordem garantida.
- [ ] `NULL` exige `IS NULL`, não `= NULL`.
- [ ] `WHERE` filtra linhas; `HAVING` filtra grupos.
- [ ] `COUNT(*)` conta linhas; `COUNT(coluna)` ignora nulos.
- [ ] Filtro no `WHERE` pode anular o efeito externo do `LEFT JOIN`.
- [ ] Alias do `SELECT` geralmente não existe no `WHERE`.
- [ ] Ordem escrita, lógica e física são diferentes.
- [ ] `SELECT` pode ser classificado como DQL ou dentro da DML.

## 21. Questões inéditas — estilo CESGRANRIO

### 21.1 Questão 1

Considere a consulta:

```sql
SELECT cod_departamento,
       COUNT(*) AS quantidade
FROM empregado
WHERE ativo = 'S'
GROUP BY cod_departamento
HAVING COUNT(*) >= 3
ORDER BY quantidade DESC;
```

Na ordem lógica simplificada, as cláusulas são processadas como

A) `SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY`.  
B) `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`.  
C) `FROM → GROUP BY → WHERE → SELECT → HAVING → ORDER BY`.  
D) `WHERE → FROM → HAVING → GROUP BY → SELECT → ORDER BY`.  
E) `FROM → SELECT → WHERE → HAVING → GROUP BY → ORDER BY`.

> [!success]- Gabarito comentado
> **Resposta: B.** Primeiro é formada a fonte; depois são mantidos empregados ativos; em seguida são formados os grupos, filtrados pelo `HAVING`; só então são projetadas as expressões do `SELECT` e o resultado é ordenado. A pegadinha é seguir a ordem escrita da consulta, apresentada na alternativa A.

### 21.2 Questão 2

Considere `DEPARTAMENTO`, contendo também departamentos sem empregados, e `EMPREGADO`. Para listar todos os departamentos e a quantidade de empregados ativos em cada um, inclusive zero, a consulta conceitualmente adequada é

A)
```sql
SELECT d.nome, COUNT(*)
FROM departamento d
JOIN empregado e ON e.cod_departamento = d.cod_departamento
WHERE e.ativo = 'S'
GROUP BY d.nome;
```

B)
```sql
SELECT d.nome, COUNT(e.matricula)
FROM departamento d
LEFT JOIN empregado e
  ON e.cod_departamento = d.cod_departamento
 AND e.ativo = 'S'
GROUP BY d.nome;
```

C)
```sql
SELECT d.nome, COUNT(*)
FROM departamento d
LEFT JOIN empregado e
  ON e.cod_departamento = d.cod_departamento
WHERE e.ativo = 'S'
GROUP BY d.nome;
```

D)
```sql
SELECT d.nome, e.matricula
FROM departamento d
CROSS JOIN empregado e;
```

E)
```sql
SELECT DISTINCT d.nome
FROM departamento d
JOIN empregado e ON e.cod_departamento <> d.cod_departamento;
```

> [!success]- Gabarito comentado
> **Resposta: B.** O `LEFT JOIN` preserva todos os departamentos; o filtro de empregados ativos no `ON` limita as correspondências sem excluir o departamento; `COUNT(e.matricula)` ignora o `NULL` gerado quando não há empregado, retornando zero. Em C, o `WHERE` elimina as linhas sem correspondência e desfaz o efeito desejado da junção externa.

## 22. Resumo de véspera

```text
SQL = declarativa, padronizada, orientada a conjuntos e com dialetos
SELEÇÃO (σ) = filtra linhas = WHERE
PROJEÇÃO (π) = escolhe colunas = lista SELECT
JUNÇÃO (⋈) = combina relações = JOIN
PRODUTO (×) = todas as combinações = CROSS JOIN
UNION = empilha e elimina duplicatas
UNION ALL = empilha e preserva duplicatas
DDL = estrutura; DML = dados; DQL = consulta
DCL = privilégios; TCL = transações
WHERE = linhas; HAVING = grupos
COUNT(*) = linhas; COUNT(coluna) = não nulos
NULL = IS NULL; comparação comum gera UNKNOWN
ORDEM: FROM/JOIN/ON → WHERE → GROUP BY → HAVING
       → SELECT → DISTINCT → ORDER BY → LIMIT
```
